2nd Slider – Profile Picture Input
Profile picture options
The user can:
•	Take Photo using the device camera 
•	Upload/Browse from gallery 
•	Choose an Avatar from predefined PEERS avatars 
Privacy statement
Your idea of displaying a privacy message is good, but I'd phrase the requirement carefully:
Your personal photos are not shared with third-party applications without your permission.
I wouldn't promise that the image is never shared with third parties unless your actual backend/privacy architecture guarantees that. For example, your cloud storage provider may technically process the image.
Image editor
After selecting/taking a picture:
•	Display the image inside a circular crop frame. 
•	User can: 
o	Zoom in 
o	Zoom out 
o	Move image horizontally 
o	Move image vertically 
•	Do not automatically crop/position the image. 
•	User manually adjusts the image until satisfied. 

Buttons:
[ Cancel ] [ Save ]
•	Cancel: Discard changes and return to the profile-picture selection screen. 
•	Save: Save the adjusted profile picture and return to Step 2. 
Final navigation
[ Back ] [ Continue ]
→ Continue to 3rd Slider – Interests
This distinction is important: Save applies to the photo editor, while Continue moves between onboarding steps.

One architectural point
Don't think of these four screens as four separate "profile pages." They're better documented as a single Profile Onboarding flow with four steps.
That distinction will help later when you implement it:
Profile Onboarding
•	Step 1 → Basic Information 
•	Step 2 → Profile Picture 
•	Step 3 → Interests 
•	Step 4 → PEERS Preferences 
Then, after completion, the user never sees this flow again unless they explicitly choose "Edit Profile."
That is a clean setup for PEERS.

Keep the all the data entered by the new user when the dashboard and profile page has been created inside the app.
